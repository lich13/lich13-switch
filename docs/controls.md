# 面板、额度与系统控制

## 快捷面板

左键反复点击菜单栏／托盘图标始终显示并聚焦独立面板，失焦后收起；固定后保留，Escape 或关闭按钮始终可关闭。供应商和账号标签记住上次选择。供应商页通过 Codex／Claude Code／Grok Build 切换客户端，可以启停对应网关、选择模式与供应商，查看优先级、当前选择和额度；满载、冷却或故障时显示异常状态，“白名单”入口编辑对应供应商的模型限制；账号页可搜索并切换。面板不会重置主窗口草稿，也不会更改 Dock 显示状态。右键菜单提供打开主窗口、配置、网关、设置与退出，普通打开保留当前页面。

## 快捷控制

快捷面板底部提供“强制退出 ChatGPT / Codex”和 macOS 电池“合盖不休眠”。桌面端的前者先给匹配的 ChatGPT / Codex 根进程最多两秒退出清理时间，再终止剩余进程，并按实际退出结果反馈。macOS 仅在确认终端已回到原用户 shell 后关闭残留的鼠标和焦点上报；前台已变更或身份无法确认时跳过，并提示重新打开对应终端。开发预览使用模拟实现；后者通过独立电源助手执行限定的 `pmset` 操作，记录本次实际电池休眠值（包括 0），关闭时只恢复仍属于本应用的修改。

macOS 首次操作需系统管理员授权安装助手；日常开关走 XPC，不重复请求密码。快捷面板点击开关后，助手缺失、版本不匹配或授权失效会直接进入系统修复授权，成功后继续本次操作；一次点击最多修复一次。取消授权、修复失败或期间电源状态被外部修改时保留实际状态。设置页也可安装、修复或移除助手。助手由系统 launchd 管理，仅接受状态读取、合盖切换与恢复；验证获授权用户、正式应用路径和实际进程的代码签名，升级导致代码身份变化时需重新授权。安装程序不保存密码、不配置免密 sudo。应用须位于 `/Applications/lich13-switch.app`；开发和隔离运行不会调用或安装正式助手。

助手位于 `/Library/PrivilegedHelperTools/com.lich13.gpt-switch.power-helper`，系统服务为同名 LaunchDaemon，恢复记录位于 root 私有目录 `/Library/Application Support/gpt-Switch Power`。恢复事务由助手统一管理。外部程序更改的字段保持当前值，再次点击可按最新状态重新操作。外部已开启时，明确关闭只解除禁止休眠，保留外部休眠时间。移除助手只恢复本应用仍拥有的字段；退出应用不改变电源状态。

## Key 额度

网关页使用供应商现有 Key，优先查询 Sub2API `/v1/usage`；未识别时回退到同一部署路径的 New API `/api/usage/token/`。支持余额、Key 配额、无限额度、订阅日／周／月窗口、5 小时／日／周限制、到期、重置及已返回的使用统计。New API 使用公开 `/api/status` 的比例和货币设置换算；信息不足时显示原始“额度单位”。不支持的站点显示“不可查询”，认证、限流和网络错误分别显示原因。

额度自动刷新默认 60 秒，在各客户端的网关高级设置中均可改为 10–86400 秒或关闭；可见供应商页面只查询已到期结果，两窗口共用后台查询。隐藏窗口或离开页面暂停，并提供单项及全部手动刷新；手动操作也会遵守 Retry-After。刷新与失败均保留上次成功结果；失败显示真实错误和重试时间，不显示缓存过期标签。额度查询通过直连与严格 TLS；不调用模型、不触发业务熔断，也不更改故障转移选择。关闭本地网关时仍可查询额度。

## 模型错误与日志

明确的模型不存在、不支持或当前 Key 无权使用指定模型，按中性结果处理，不累计整家供应商的熔断失败。自动模式在尚未输出且上下文安全时尝试下一家；手动模式、固定上下文和已建立的原生 WebSocket 不迁移。真正的认证、网络、服务故障及容量限流继续执行原策略；白名单不自动更改。

“日志”显示异常和重要状态，保留时间、客户端／供应商、状态、问题和处理结果五列。摘要旁区分普通错误、熔断错误和状态记录，可按类别、时间、客户端、供应商、级别、原因及 2xx／4xx／5xx／无状态码筛选。实际熔断事件及其关联触发错误才标记为熔断错误；详情保留脱敏错误码、原因和触发条件。记录仅保存在本机，保留 7 天且不超过 5 MiB；不保存请求／响应正文。

自动系统提醒只保留实际熔断和线程接管成功，默认启用，可在设置关闭。熔断按客户端、供应商和健康作用域五分钟合并，模型与接管通知分别去重。等待取熔断冷却与有效 `Retry-After` 的较长限制；通知显示剩余等待，日志保留发生时等待与预计探测时间，旧记录缺少依据时显示未记录。主窗口和快捷面板倒计时结束后显示“待请求探测”，实际探测中显示“恢复探测中”。静默启动不申请系统权限，首次主动打开应用时按系统流程授权。

## 系统通知

设置中显示实际通知权限，提供“发送测试通知”和“系统通知设置”。macOS 授权、状态查询及发送使用同一原生通道，支持前台显示；Windows 使用安装身份对应的 Toast。首次主动打开可申请权限，静默启动不弹授权。

自动推送仅发送实际熔断和线程接管成功。未实际熔断的模型缺失、认证错误、最终请求失败和配置异常只记日志；手动测试通知不受该自动分类限制。

同一问题在系统接受后才进入五分钟提醒抑制；发送失败显示脱敏原因，并进行有界重试。日志合并与通知去重分别处理。“系统已接受”只表示操作系统接收了请求，不代表通知已经显示或被用户看到。

请求取消、网关停止及下游交付异常只写日志，不触发系统推送。关闭原因分别保留明确取消、连接重置、写入失败、写入超时、响应体释放或未知关闭；同类交付记录在一分钟内合并，详情保留最近一笔的持续时间、已读取／交给传输层的字节数及终态证据。交给传输层不等于客户端已收到，读取方向的 TCP 半关闭也不等于取消。
