# 客户端网关与调度

主面板与快捷面板分别记住 Codex／Claude Code／Grok Build 选择，切换视图不改变实际连接。供应商、队列、并发、熔断、模型限制、额度缓存及启动恢复按客户端隔离，供应商请求统一直连。三个网关可同时运行。

## 共享监听

新安装默认共享 `127.0.0.1:43721`。Codex 和 Grok 使用 `/v1`，Claude 使用根地址；所有 `/v1` 请求按客户端独立令牌精确分流，包括 Grok 也支持的 `/v1/messages`，不根据模型或协议猜测客户端。支持 `Authorization: Bearer` 和 `x-api-key`；同时提供时必须匹配同一客户端，重复或不匹配的认证头返回 401。旧 `/codex`、`/claude`、`/grok` 前缀在当前共享端口继续作为对应客户端的别名。转发只移除旧本地前缀，剩余路径、查询参数、正文、SSE 和 WebSocket 保持原有转发规则。

无前缀地址必须携带本客户端的本地令牌；缺失、错误或同时匹配多个客户端时返回 401，不会兜底交给 Codex。Bearer 认证方案名称不区分大小写，令牌本身仍须精确匹配。

共享端口保存在 `gateway-listener.json`，高级设置只有在全部网关停止时才允许修改。监听配置迁移只在没有客户端运行时进行：

- 文件缺失：已有安装继承旧 Codex 配置端口，新安装使用 43721。
- 版本 1、旧默认 15722：新端口绑定成功后迁到 43721；若新端口不可用且旧端口可绑定，保留旧端口并提示一次。两者都不可用则报错，不提交迁移。
- 版本 1、自定义端口：原样保留端口，只更新配置版本。
- 版本 2：不重复迁移。

首次启用先绑定端口再提交配置；停用一个客户端只终止其请求，其他客户端继续服务，最后一个停用后释放端口。升级通过已有事务迁移 Claude、Grok 的旧本地地址，不继续监听旧端口；已缓存旧地址的客户端需重新打开，应用不会自动重启它们。

共享端口迁移成功后会提示实际新端口。已经打开的 Codex／Claude Code／Grok 需要重新打开，才能读取更新后的地址；自定义端口原样保留时不会提示端口已迁移。

## Codex

Codex 支持两种连接方式，在网关高级设置中选择：

- **独立 Bearer Token**：沿用现有 `custom` 配置，只写 `base_url` 与 `experimental_bearer_token`，不修改 `auth.json`。
- **普通 API 登录**：使用 `auth.json` 的 `OPENAI_API_KEY`，仅修改该文件和当前选中供应商的 `base_url`。保留原有 provider 名称、profile、模型、协议、WebSocket 开关及其他 TOML 字节。

首次启动只读识别已有连接并导入供应商；已使用本应用的安装保留原连接方式。普通 API 模式要求当前供应商已启用 `requires_openai_auth`，且凭据存储采用文件；若存在 Keyring、强制 ChatGPT 登录或独立认证配置覆盖，会提示原因，不自动清除它们或改写认证配置。网关运行或存在恢复事务时不能切换连接方式。

普通 API 网关运行期间，本地临时 Key 不会进入账号库；切换账号须先关闭网关。两文件写入有版本校验、回读和崩溃恢复，`auth.json` 的其他字段保留。

启用先绑定共享回环端口，再将两字段替换为本地地址和访问令牌。运行时切换供应商只更新内部路由，新请求生效，进行中的连接保持原供应商。关闭网关时选择供应商会直接写入其地址和 Key。**停用或正常退出写入当前供应商，不恢复启用前供应商**；自动模式使用最近成功响应的供应商，没有成功记录时使用队首。写入文件后需要重新打开 Codex，不自动重启客户端。

两字段受到外部修改时停止覆盖并保留事务记录；其他字段的外部编辑会保留。异常退出后，下次启动按同一事务完成写入。旧版已经解除接管的失效记录只清理元数据；仍由旧 provider 接管时提示处理，不执行旧版整份配置回滚。更换 Codex 目录前须先停用网关。

网关只转发发往供应商 `base_url` 的 API：未知路径、Responses、compact、models、搜索、图片和上传均使用同一原始载荷通道，包括 SSE 和 WebSocket。登录、插件和 MCP 的其他地址不经过网关。供应商地址在保存时按现有规则规范化，缺少版本段时补 `/v1`；转发保留部署子路径，本地 `/v1` 前缀替换为上游 base 路径。重定向原样返回。Bearer 认证替换为上游 Token，连接头按 HTTP 规范处理，模型和业务参数不重写。

网关按客户端原协议转发 HTTP、SSE 和原生 WebSocket，保留请求内容、流式载荷及必要的上游认证替换；不再提供供应商 WebSocket 能力勾选或 HTTP/SSE 桥接。WebSocket 首事件前断开等待重连、429 容量持续等待、上下文归属、逐轮并发与 RPM 保护继续有效，已输出后不重放。

Codex Responses WS 两端空闲 20 秒发送 Ping 保活，不延长生成超时。每轮首个业务事件输出前，明确容量、账号拒绝或模型不可用可在上下文和接管资格允许时换商，保持客户端连接并发送同一原始请求；暂时容量错误没有替代时释放并发并等待重试。首个业务事件输出后的错误保持原事件，不重放。

自动模式按线程归属和供应商优先级检查模型、上下文、健康与容量并原子预占，状态竞争时重新检查一次。除原供应商的短暂故障重试外，每家每轮最多一次，普通网络／服务故障默认最多四次实际上游尝试（首次请求加 3 次重试）；Codex 和 Grok 暂时容量错误使用独立等待轮次，不消耗普通故障预算。满载或健康跳过不消耗上游尝试次数。普通故障默认连续失败 4 次，错误率阈值为 60% / 最小 10 次，采用最近 60 秒、最多 1024 个样本；恢复等待 60 秒、半开 2 次成功，半开只放行一个探测。HTTP 500–599 服务错误统一采用最近 60 秒连续 6 次的阈值，可在高级设置调整为 1–1000 次；成功后清零，未达阈值不触发熔断或单供应商冷却，也不混入普通故障错误率。有效 Retry-After 仍会执行。Codex 线程已有归属时，普通 5xx 先在原供应商等待 1、2 秒重试（更长 Retry-After 优先），最多两次并计入普通重试预算和 RPM；尚未输出且上下文允许时，持续故障或明确额度耗尽才尝试其他供应商。首字节和流静默默认各 600 秒；持续收到数据的流式及非流式响应不设总生成时限。请求上传单独限时，连接、首事件和下游背压按各阶段的真实进展判断。旧默认值自动升级，自定义值保留。`400/405/406/413/414/415/422` 直接返回且不计故障；客户端取消为中性。Codex 和 Grok 的临时 429，以及 503/529 等响应正文含容量提示时进入容量重试：先按队列换商，没有可用替代时等待“容量错误等待 / 秒”（默认 60，较短 Retry-After 仍不低于此值）再从 P1 重试；自动队列仅剩一家时保持独立冷却保护，不进入彻底熔断。其他限流仍使用独立冷却，有效 Retry-After 按原时长执行，无有效值默认 5 秒；Claude 沿用该限流策略。服务故障熔断与容量／限流冷却分别计算，恢复时最多一个并发探测。已向客户端提交输出后不重试，WebSocket 已输出业务事件后不换商；已知 previous_response_id 固定原供应商；未知归属不跨供应商重放，容量等待仍固定首次选择的供应商。gzip / deflate / zstd 和磁盘暂存的 JSON 只流式读取路由归属，原始载荷不变；无法解析的 JSON 或未知压缩编码保守地只尝试一次。

请求最多 1 GiB，超过 2 MiB 使用权限受限的临时文件重放，完成或取消后清理。目标连接、TLS 和 HTTP 故障归对应供应商。调度层只维护当前路由、冷却和并发状态；启用用量记录时，由独立用量模块保存请求元数据、已报告 Token 和估算费用，不保存请求或响应正文。故障转移来源和改动见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)。

## Claude Code

默认读取 `CLAUDE_CONFIG_DIR` 或 `~/.claude`；旧安装中的目录偏好继续兼容。首次从现有 `settings.json` 导入供应商，网关保持关闭。添加表单仅填写 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN`。

网关操作仅替换 `settings.json` 中 `env` 下的这两个字段。缺少文件、env 或字段时补齐必要结构；其他字段、顺序、缩进和换行保留。无效 JSON、重复受管键或非字符串值停止操作。不会修改 shell 启动文件、环境变量、模型、权限和插件。检测到的其他认证来源仅提示，项目或组织的更高优先级配置仍由 Claude Code 决定。

Claude 使用共享根入口 `127.0.0.1:43721`，客户端继续追加原生 `/v1/messages` 等路径。请求路径按原有规则附加到供应商地址的部署子路径；旧 `/claude` 别名会先移除本地前缀。HTTP、SSE、工具调用、原始载荷及 Anthropic 协议头保持，认证替换为对应供应商 Bearer Token。原生模型列表读取 `/v1/models` 并处理分页。参考 [Claude 配置](https://code.claude.com/docs/en/settings) 和 [环境变量](https://code.claude.com/docs/en/env-vars)。

Codex 与 Claude 启停及换商使用相同事务：先监听再接管，热切换不写配置，停用或退出写回当前供应商；自动模式写回最近成功供应商、无成功记录则队首。文件变更提示重新打开对应客户端。三个本地网关地址均禁止作为上游。

供应商的“端点”入口可以添加辅助 `base_url`，也可将任一辅助地址一键设为主地址，原主地址保留为辅助地址。网关默认每五分钟比较连接响应延迟，新连接优先使用较快的可达地址；间隔在高级设置调整。已绑定线程、响应游标和重连保留实际端点，测速不调用模型或占用业务 RPM。主副地址必须属于同一供应商、使用同一 Key；网关关闭时仍恢复当前保存的主地址。新线程首次绑定必须先保存归属；保存失败只拒绝该绑定，重试仍保留原候选。已有归属的定时刷新保存失败会保留旧端点并记录普通诊断，不阻断已有归属的请求。

## Grok Build

默认读取 `GROK_HOME` 或 `~/.grok` 下的 `config.toml`，本地入口为 `127.0.0.1:43721/v1`。供应商表单选择 `responses`、`chat_completions` 或 `messages`，只向协议匹配的供应商转发；模型和原始内容保持不变。识别完整自定义模型、内置模型局部覆盖、共享供应商、全局端点和显式环境变量，分别处理模型的 `base_url` 与 API 认证地址 `api_base_url`。未知协议或认证方式保留为未识别，不猜测。

首次发现只读展示。在“导入当前配置”预览模型、协议、地址来源及凭据可用性；桌面应用未继承终端变量时，可明确勾选读取 Grok 目录中 `endpoint.env` 的简单赋值。文件不会被执行，不支持命令替换或变量展开。确认后，将当前 API 连接和已有模型参数迁入 `lich13-switch` 模型项，默认继续选择 API；已迁移的全局端点、API 登录固定项和内置模型凭据覆盖会撤除。其他配置、注释、MCP 和工具设置保留。配置、环境文件与私有供应商库采用版本检查和可恢复事务；取消不写入，重复导入不重复添加供应商，外部冲突保留现场。

导入后，在 Grok 中选择 `lich13-switch` 使用 API，选择官方模型使用 `grok login` 管理的登录。启停网关仅调整受管 API 模型连接；运行中可切换原生默认模型，停用不会覆盖这个选择。旧安装在明确导入前继续保留原受管选择与“恢复原生配置”规则。运行中切换 API 协议需先停用网关；配置页可编辑 TOML 原文。供应商不支持额度查询时显示不可用。

旧终端已继承的变量不会随环境文件迁移而消失。导入完成后按弹窗给出的 `unset` 变量列表清除当前终端变量，或重新打开终端，再运行 `grok login` 并选择官方模型。官方 OAuth 凭据由 Grok 登录和刷新，不导入供应商队列，也不自动执行外部认证命令。模型自身的 API 凭据优先于全局登录偏好，因此官方登录和 API 模型可以分别使用。

Grok 使用普通请求准入，不套用 Codex 的新线程／压缩接管开关或 300 秒线程预留。容量型错误先尝试合格替代，没有替代时释放并发并等待有效重试限制，取消和停止会退出等待。

## 供应商模型白名单

在供应商更多菜单打开“白名单”，直接选择不限模型或编辑非空白名单；白名单在当前弹窗直接编辑和保存。完整模型 ID 区分大小写，去除首尾空白及重复项，不支持通配符。可从供应商读取模型、搜索勾选，也可手动输入；读取失败不清除选择，刷新不会自动增删白名单。模型接口为填写的 `base_url` 后追加 `/models`，不猜测 `/v1`；查询使用已有 Key 和直连连接，10 秒超时、2 MB 上限、5 分钟缓存，凭据或地址变化后失效，不调用模型或消耗业务并发。

**白名单只在网关运行时生效，不写入 Codex 配置。** HTTP/SSE 从 JSON 或 multipart 读取模型，兼容 gzip、deflate、zstd，原始载荷不变。模型筛选先于健康、并发和排队；不匹配不计故障或重试，等待期间规则变更会重新检查。手动模式同样受限。已知响应游标固定原供应商，模型省略可继承已知上下文；没有可靠依据时只使用不限模型的供应商。没有匹配项返回 `400 MODEL_NOT_ALLOWED`，无法识别且没有不限供应商返回 `400 MODEL_UNDETERMINED`。明确的文件／模型等资源接口正常透传。

Responses WebSocket 每个 `response.create` 检查模型，连接建立后固定供应商；后续轮次可继承已确认模型，规则更新从下一轮生效。不匹配时以 `1008` 关闭，不向上游发送该轮内容。未知 WebSocket 协议只允许不限模型供应商，仍按整条连接占位。

## 并发与启动

主面板与快捷面板的并发和 RPM 按钮可分别调整上限，整数 `0–100000`，`0` 表示不限。RPM 按客户端与供应商隔离。设置为 N 时首个请求立即发送，之后相邻发送至少间隔 60/N 秒（向上取整到毫秒），空闲不积累突发额度；10 RPM 对应至少约 6 秒。发送和成功完成分别检查最近 60 秒窗口，并保留 1 秒边界余量；已发送未结算的请求预留完成名额，防止长流集中完成。真实上游尝试不因失败、429 或下游断开退还发送计数；明确失败释放完成名额，结果未知则保护到结束后 61 秒。取消尾读观察到的真实成功只结算一次。

达到本地 RPM 后释放业务并发并固定当前供应商排队，不触发熔断或自行换商。界面使用数仍是发送次数，等待提示分别说明发送节奏、发送窗口、完成窗口保护或上游退避。只有明确 RPM 证据才设置供应商级退避；普通容量错误保留原作用域。有效 Retry-After 支持整数、小数及 HTTP 日期，发送取本地限制与上游退避的最晚时间。发送、完成、在途保护与退避保存在独立私有账本，发送前原子保存；已启用限速时账本不可用会保守拒绝。旧账本保留发送历史，并采用一次 61 秒初始化保护；崩溃遗留请求和时钟回拨不会靠重启清空限额。重置熔断不清除 RPM 记录。队列开关直接加入／移出；拖动左侧手柄重新排序，列表顺序决定自动队列的 P1、P2，未入队项不占编号。键盘空格拾取、上下移动、空格确认、Escape 取消。排序与快捷调整不改变当前选择、路由模式或 Codex 文件；降低并发或 RPM 上限不终止已有请求。设置保存失败保留输入，其他窗口修改后需使用最新状态重试。

HTTP/SSE 从上游转发开始占用到响应结束，取消或失败自动释放；额度和模型查询不占业务名额。自动模式跳过满载供应商，优先分配给下一家；高优先级供应商恢复空闲后重新优先使用。满载不计入失败或重试。所有匹配候选满载、冷却或恢复探测中时，共用默认累计等待 30 秒、最多 100 个请求的 FIFO 队列；唤醒后重新检查规则与优先级。参数可在高级设置修改。队列满或容量超时返回 429 与 Retry-After: 5；冷却超时返回 503 PROVIDERS_COOLING_DOWN 和重试时间。模型不匹配、队列为空等确定性问题立即返回；已有上游尝试全部失败时保留最后一次上游错误。手动模式及已有响应游标绑定的请求仅等待对应供应商。Codex 已收到容量错误后的重试等待采用独立的容量等待时长，不消耗响应读取超时；与并发队列共用等待人数上限，取消或停止网关立即退出，等待结束后重新读取队列、白名单和健康状态。Codex 进入暂时容量保护后，普通 30 秒准入超时不再提前终止请求；暂时 429／容量错误持续等待，直至恢复、取消、断开或停止网关。每次真实发送仍计入 RPM，全局等待人数和并发限制继续生效。明确余额耗尽、账号禁用等永久拒绝先尝试其他合格供应商，无替代时结束；`USAGE_LIMIT_EXCEEDED` 单独出现不算永久拒绝。客户端自身超时仍会结束请求。

明确日／周／月额度耗尽优先于通用 403／429 和容量分类，立即排除本次逻辑请求中的供应商与凭据版本，尝试合格替代；无替代时保留错误并结束。已有可靠归属的线程遇临时容量限制继续等待原商。`USAGE_LIMIT_EXCEEDED` 缺少耗尽证据时，在释放业务并发后启动一次有界的只读额度核验；仅本轮新查询明确确认耗尽才允许尝试替代。查询总时限 10 秒，包含排队和接口探测；同供应商与凭据版本合并并发查询，连续触发至少间隔 10 秒并尊重额度接口 Retry-After。关闭周期刷新不关闭此次核验，也不等待显示币种接口。

新查询有剩余、失败、不支持、超时或证据不足时继续原等待，查询耗时不再叠加一轮倒计时。钱包／适用订阅／当前 Key 的额度依据单独核验，精确原始数值不经过界面舍入；多套餐适用项不明、数据矛盾或仅钱包为零但可能使用订阅时保持未知。正余额不保证请求可用，旧缓存不能授权切换。取消、停止、重置或凭据变化终止对应等待及无人使用的查询；手动模式、响应游标和已输出内容的重放边界继续生效。

Responses WebSocket 按每轮 `response.create` 生成计数，空闲长连接不占业务名额。首轮读取后选路；后续轮次固定已有上游，等待超时以 1013 关闭，请客户端重连。通过协议处理识别轮次和压缩／分片，消息内容不重新序列化；Ping/Pong、关闭信息与背压保留。单条 Responses WebSocket 消息上限 64 MiB，最多额外缓存一轮生成；未知 WebSocket 路径继续使用通用隧道，并按连接计数。

设置中提供开机静默启动；启动恢复固定启用，依据各网关上次保存的启用意图执行。macOS 使用用户级 LaunchAgent，Windows 使用当前用户启动注册；仅在用户开启后注册。应用正常退出仍将配置写为当前供应商，并保留上次开启意图；明确停用网关会清除该意图。下次启动检查客户端目录和受管配置指纹，先完成崩溃事务，再绑定端口并接管两字段；外部修改受控字段、端口占用或配置不满足当前连接方式时显示错误，不覆盖现场。

macOS 通过用户级 LaunchAgent 和系统的登录启动 Apple event 识别启动来源，兼容系统忽略旧登录项隐藏属性的情况；手动打开仍显示窗口。Windows 使用专用登录启动参数，重复的登录启动信号不弹出窗口。

切换应用、Dock 重新打开或托盘普通打开保留当前页面、弹窗与内存草稿。明确导航离开未保存的供应商表单时需要确认；取消或退出清除草稿中的凭据。

## 断开等待与错误明细

Codex Responses WebSocket 在本轮首个事件前断开时，保留客户端连接，默认等待 60 秒后重连原供应商；可在网关高级设置调整为 1–86400 秒。已发出 response.created 或其他事件后不重放，避免重复输出；已绑定的模型与 previous_response_id 不改写。等待可取消，停止网关立即退出；并发释放，每次发送继续计入 RPM；普通传输错误使用最大重试次数，暂时容量错误独立持续等待，更长的健康冷却仍生效。

已识别的正常下游关闭、连接 reset、BrokenPipe 和传输取消归为 Info／状态，保留具体原因及“未确认客户端主动取消”的事实；写超时、协议错误及未知 I/O 仍告警。上游终态已收到但未完整交给下游时显示“上游已结束，下游未完成交付”，保留真实 HTTP 状态、字节数和原始交付原因。日志只展示允许名单中的上游 reason 与本次额度核验结论，不记录余额金额或原始额度响应，也不回填历史原因。

日志将 HTTP 状态与 WebSocket 关闭码分开显示，记录有界、脱敏的上游 code/type/param/message、错误阶段和处理动作。模型错误不计入熔断；熔断详情关联真正的触发错误和阈值。恢复日志不再生成，旧恢复记录隐藏。

用量表采用时间、客户端／供应商、模型、输入、输出、缓存、费用七列，模型优先显示实际响应值，详情保留请求／响应／计价模型与价格快照。缺少响应模型价格时保持“未定价”，不替换成请求模型价格；明确设置按请求模型计价时仍遵守设置。

`/v1/alpha/search` 与 `/alpha/search` 作为“网络搜索”计费：每次确认成功按 USD 0.01 乘用户成本倍率，不重复计算 Token 费用；失败或取消且未确认成功不补造费用，历史缺少可靠操作元数据时不猜测补算。

## 压缩识别与压缩后接管

Codex 网关识别 `/responses/compact`、`/v1/responses/compact`、输入中的 `compaction_trigger` 和实际返回的压缩项。请求表按需标记“压缩”，按上游报告的 Token 计价；gzip 等传输编码不算上下文压缩。普通 JSON、SSE 和本机会话采用有界增量元数据解析，保留大响应末尾用量；支持 gzip、deflate、zstd 和 Brotli。协议已经完成后断开不会改记为取消；客户端仍连接时尾部继续转发，统计解析上限不截断响应。

Codex 每个供应商可独立设置“压缩后接管”和“新线程接管”，新供应商和缺失字段默认关闭，升级保留明确保存的独立值。两个开关关闭时按普通队列；开启后仅新接收对应类型。可靠首轮优先检查新线程接收方，再检查普通候选，不能绕过 RPM、并发或白名单。

已有线程维持原供应商，开关关闭不会解除归属。压缩仍由原供应商处理；成功后下一条携带对应完整压缩窗口且不含旧 `previous_response_id` 的请求，才尝试排序更高、允许压缩后接管的供应商。没有合适目标时保留原供应商。HTTP 与 WebSocket 共用归属，所有请求仍受白名单、健康、并发和 RPM 约束。

原供应商仍在队列、但不支持当前请求的明确模型时，只让本次请求绕行到合格的普通供应商。绕行及其重试不改变线程归属，不领取或消耗压缩窗口，也不新增或刷新线程预留；实际请求仍计入承接方的并发、RPM 和用量。后续主模型请求继续遵循原归属。请求详情显示“模型绕行，线程归属保持”；“最近使用”仍是跨线程最近成功请求的实际供应商，不代表某个线程的绑定状态。响应游标固定和 WebSocket 连接约束继续生效，绕行不新增接管通知。

绕行产生的响应游标继续固定到实际承接方，但不会因此获得修改线程归属的权限。WebSocket 绕行连接上的后续请求若不带响应游标，且应由仍可用的主归属供应商处理，会在发送前按现有错误通道拒绝，不在该连接上任意换商。

升级不会重写已有线程归属；旧线程继续按正常压缩接管规则处理。等待期间配置或归属变化使发送授权失效时，停止该次发送，新的请求使用当前规则重新判断。

线程归属优先读取 Codex 的 `thread-id`，兼容旧线程标识；缓存亲和性 `session-id` 不作为线程身份。预热请求不提前建立归属，真正生成时再按首轮结构与接管资格原子选择。多条初始化消息不会使有效的新线程被误判为续接。

WebSocket 只在轮次间更换上游，已输出内容不重放。新供应商不接受压缩上下文时，在未输出且允许重试的条件下回到原供应商，不把兼容性拒绝算作线路故障。没有可靠线程标识或仍依赖原响应游标时不跨商猜测；供应商被明确移除或确实故障时保留现有路由规则。不同供应商不一定共享缓存或压缩密文，无法保证每次接管都节省上游费用。

## 套餐与线程接管

ChatGPT 账号标签读取已有凭据中的套餐及工作区信息，不额外登录；缺少可靠信息显示“未识别”，凭据过期不会被当作套餐到期。供应商额度接口明确返回的套餐名称、周期和有效期在额度详情展示，与余额和 Key 配额分别处理。

Codex 供应商第二行可直接切换“压缩后”“新线程”。新供应商默认全关，按普通队列工作；开启后只新接收对应类型的线程，两项都开时接收任一种。进行中的归属保持不变，重试及故障转移同样检查接收资格。没有符合条件的供应商时返回 `NO_ELIGIBLE_PROVIDER`，已有上游尝试则保留其真实错误。

## 接管容量与线程预留

压缩接管会同时检查接收方并发、RPM、白名单、健康和队列，只主动尝试排在原供应商前方且开启压缩接管的接收方。没有更高优先级的合格接收方时继续留在原商；原商移出队列后，仍可依据匹配的新鲜窗口评估当前队列的接收方。健康冷却不清除线程归属。

本线程真实生成首次成功交给传输层后，旧窗口失效，包括 `response.created`、普通续写和接收方满载后由原商生成。预热、控制帧、资源请求、模型绕行及固定在其他供应商的旧游标请求不消费窗口。压缩操作本身不消费旧机会，成功终态和交付条件满足后才登记新窗口。

未输出即取消或失败会释放领取并保存，正常保存后重启仍可使用该机会；已经输出则不恢复，崩溃留下的未完成领取也不会复活。旧请求不能清除新代次的边界或覆盖新归属。原生 WebSocket 后续轮次读取账本当前归属，游标固定和模型绕行连接继续遵守原有限制。

详情和日志保留线程身份类别、边界状态、路由判定及关联尝试，不保存原始线程标识或请求内容。“正在尝试接管”与“线程已接管”分别表示领取中和归属已保存；保存失败作为错误显示，不发送接管成功通知。等待提示保持中性，不新增系统通知。

Codex 自动模式中，可靠识别的线程在最后一个在途或等待请求结束后默认保留名额 5 分钟；有新请求重新计时。并行请求仍分别占用名额，接管后旧供应商的名额也要达到空闲条件才释放。可在高级设置修改“线程空闲释放 / 秒”；并发浮层分别显示正在请求与线程预留。

“白名单”入口只管理模型限制。用量列表按结束时间排列并显示到秒，详情同时给出开始、发送、协议终态和本地结束时间；上游按数据库 ID 排序时，并发记录的顺序仍可能不同。断开诊断分别记录上游读取、交给 HTTP／WS 层、连接累计 socket 写出，以及有序的 EOF／RST、读写失败、响应体取消和网关停止事件。连接计数可能包含复用请求，不代表单个请求或客户端实际接收；上游终态与下游交付异常独立保留，不根据 HTTP 200 或上游计费判定交付成功，缺少终态证据时保留未知。

## Sub2API 供应商文件

在网关选择“导入”或“导出”。首次选择完整 Sub2API 导出文件作为模板；首次合法导入可同时保存模板，多个适用账号可选择其中一个作为原型。支持 OpenAI／Anthropic 的 API Key 供应商，确认前可部分选择或全选。导入不会自动入队、选择供应商或开启网关。网关入口不转换 OAuth 或绑定代理的账号；官方 OAuth 使用账号页的独立导入导出。

API Key 导出每项克隆原型，仅修改 `name`、`credentials.base_url`、`credentials.api_key`；其他字段及根级包装、已有 `exported_at` 保持原值。旧版简化模板需重新选择完整原文件。带 `data` 包装的输出对应后台请求，Sub2API 前端上传使用其中的 payload。

模板与凭据由 Rust 私有存储管理，原文件不变；导出文件包含真实凭据。地址缺少版本段时补 `/v1`，已有版本与部署前缀保留。

同一供应商内，模型限流和模型执行错误分别冷却；明确的全局认证、共享余额或连接错误才影响整家线路。压缩接管只在本次有效窗口后的首条请求尝试，原供应商已经输出后等待下一次压缩。请求表使用结束时间，与上游数据库的入库顺序不一定逐条相同。

传输故障只在尚未收到任何响应数据时允许安全重试。首字节超时还必须能证明请求尚未交给传输层；已经发送、可能发送或无法确认时，按超时结束，不向原供应商或其他供应商重放。HTTP 已收到 200 响应头时保留状态并中止未完成的响应体，不伪造完整响应。请求详情保留 `FIRST_BYTE_TIMEOUT` 和禁止重放的退出依据。不完整的 HTTP 响应前缀或 WebSocket 数据帧也视为已开始响应，不能因首个完整事件尚未解析而重放；明确、完整的首事件拒绝仍使用现有换商规则。端点归属先持久化后更新内存，写盘失败不发送请求，重试保留同一待提交归属。
