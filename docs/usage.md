# 用量、会话同步与定价

“用量”显示本网关、本机 Codex／Claude Code 会话，以及独立的 Grok 轮次汇总。网关按最终请求计数，Responses WebSocket 按生成轮次计数，重试详情及实际消费保留。HTTP 成功率采用真实状态码；会话没有 HTTP 状态时显示“会话”，不伪造成功响应。该口径独立于熔断判定，HTTP 200 内的应用错误仍会出现在异常日志中。

顶部集中客户端、供应商、计价模型、数据来源和时间筛选，自定义起止时间在时间弹层内设置。四项主指标为估算费用、已报告 Token、缓存命中率和平均首字。连续指标区下方直接展示明细，不再显示请求数指标、展开指标、趋势图或热力图；可按生成、压缩、搜索筛选。请求、供应商和模型表均每页 20 条，支持跳页；刷新保留当前内容、页码和筛选。页面刷新默认 30 秒，可关闭；额度查询继续使用自己的间隔。

“数据来源”集中网关记录、会话同步开关、手动同步及三个客户端的分别重建，并显示同步进度和导入、合并、关联待确认、失败数量。主页面不再常驻显示待核对提示和历史来源限制；数据归属可在来源面板或请求详情查看。重建采用事务，不删除网关记录；出现失败继续使用原数据。

Codex 优先读取单次 Token，缺失时使用累计差分；识别重复快照、多限额通道、累计重置和分叉重放。Claude 按消息 ID 合并主／子代理记录，保留中断时已报告的输入和缓存消耗，后到的完成项可以补全用量。跨来源优先按响应／消息 ID 合并，无 ID 时在时间窗口内按客户端、模型和各类 Token 做唯一匹配；多个候选标为“待核对”，不强行合并或混入合计。网关保留真实状态和耗时，精确响应／消息 ID 关联的会话可逐字段补齐缺失用量；真实零值不会被替换。本网关筛选只显示网关原始采集值，全部记录可显示补齐结果。详情区分上游未报告、提前结束、解析不完整和会话补齐。

Grok 原生 `turn_completed` 是一轮多次模型调用的汇总，使用“Grok 轮次汇总（独立）”来源查看，不与网关请求合计。输入拆分为非缓存输入、缓存读取和缓存写入，输出中的 reasoning 不重复相加；缺失字段保持未知。模型排行显示调用次数，多模型日志展示整轮 Token，模型筛选只汇总所选模型，详情仍保留完整轮次。无法可靠关联到网关时保持来源独立，轮次汇总不估算费用。

供应商／模型表显示名称、请求数、Token、费用、成功率和平均首字，上游尝试收进请求详情。请求数只计最终请求，实际消耗仍归属各次尝试。输入缓存按客户端协议归一化，推理 Token 不重复加到输出。明细默认 30 天，历史按用户时区整日汇总；无法逐条恢复的旧日汇总会保留并标明边界。已删除的旧网关数据无法恢复，现有会话可以重新导入；重建不重算已经计价的历史快照。

平均首字衡量供应商响应耗时：从最终一次上游请求开始发送，到首个非空文本、推理或工具参数增量，包含该次连接和上游等待，不包含本地排队、RPM 等待及此前失败尝试。只使用有真实测量的网关流式生成请求，以首字总和除以有效样本数；本机会话、非流式和搜索不推算。无样本显示“—”，真实零毫秒保留，悬浮或键盘聚焦可查看精确值和样本数。旧日汇总没有首字信息时不会补造样本。

自动定价使用 Sub2API 配置的公开价格源 `Wei-Shaw/model-price-repo`，默认启动检查，此后每 10 分钟检查；SHA-256 完整校验通过后替换缓存。来源采用增量维护，检查成功不表示所有模型已更新至官方最新价格。价格检查独立于会话扫描与历史补算；JSON 与哈希暂时不同步时有限重试，失败继续使用缓存。通常无需导入文件，文件操作收在高级菜单。手动价格和批量导入默认固定，支持恢复自动来源、筛选同步模型、排除项、独立定价文件和重新载入。

请求数和 Token 采用十进制 K／M／B，最多三位有效数字，悬浮、键盘聚焦及详情可查看精确值。请求表保持紧凑七列，数字右对齐，滚动限于表格。详情按基本信息、Token、费用、性能和尝试记录分组。来源筛选可选择“全部（去重）／本网关／本机会话”，联动概览、排名和明细；纯会话来源不借用网关首字测量。

定价页的“计费设置”集中计价模型、成本倍率和供应商精确映射。映射按客户端和稳定供应商 ID 隔离，默认关闭。规则匹配请求模型或收到的响应模型，只改变计价，不改变请求、白名单或路由；启用规则优先于通用计价模型选择，每次尝试保存规则版本和价格快照。上游隐藏内部模型且未提供可靠映射时，应用无法还原真实模型，不会自动套用更贵模型或统一倍率。

费用为 USD 估算值，支持缓存时长、服务等级、长上下文和已报告的媒体 Token 维度。信息不足时显示“未定价”，不猜测相似模型。已计价记录保留当时单价和倍率；新价格只用于新请求及历史未定价记录。

## 缺失用量与当前故障

Responses 流内有可靠响应标识的普通 `error` 等待同一响应的明确终态；随后正常完成可消除临时错误，没有后续终态则保留错误。未知原因的 `response.incomplete` 显示“上游未完成，原因未确认”。详情按需显示终态事件、状态、有限的未完成原因及上游响应关联摘要，原生 WebSocket 的握手摘要可由多轮共享。上游成功与下游交付异常分别保留，HTTP 200、用量和扣费均不单独证明成功；旧记录不补猜。

表格缺失字段显示“—”，详情与悬浮可查看未报告、提前结束、解析不完整、历史缺失或不适用。已知完整输入量及缓存读取即可计算 Codex 缓存命中率，不将未报告的缓存写入填为零。精确响应／消息 ID 可逐字段合并可靠会话元数据；本网关筛选保留实际采集值，全部来源可显示补齐值及来源。修复分批续行，历史已计价快照保留；没有原始依据的数据不推算。

日志保留数字和字符串上游错误码。连接超时、TLS 验证失败、断流等本地分类与上游返回码分别显示；最终失败和熔断继承实际触发原因。快捷面板显示当前故障及剩余等待时间，可打开关联日志。

请求详情中的结束原因区分协议完成、客户端断开、主动取消、网关停止和上游中断，并显示本次线程调度判定。HTTP 200 只代表实际响应状态；尚未收到完成事件便断开时，完成状态保持未知，不能仅凭已报告 Token 判定成功。已收到完成事件后再断开仍保留完成结果；历史缺少结束原因的记录不猜测补齐。
